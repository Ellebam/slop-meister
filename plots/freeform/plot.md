As work proceeds, use the workspace root's single `<name>-NOTES.md` as the only vault ledger, create it on first vault access if absent, and reuse it after any context refresh. The moment you first open a vault note, add `<vault-relative path>, explored` unless that path already has a ledger line. Before the first create or edit, if that path's ledger line does not already carry first-touch state, use `~/.vault-git/bin/vaultgit status --porcelain --untracked-files=all -- <path>` and whether the path exists to add or replace that path's single line with `<vault-relative path>, first-touch <state>`, where state is `clean`, `absent`, `dirty` or `unknown`. Staged, unstaged and pre-existing untracked content are dirty, an absent path is eligible only when this session creates it, and unavailable Git evidence is unknown. After each write, replace that path's line with `<vault-relative path>, edited, first-touch <state>, sha256 <digest>` using `shasum -a 256`. Later writes update that same line and digest while keeping the original first-touch state. Never append duplicate history for a path. Unopened search hits do not belong in the ledger. Harvest uses this record to bound housekeeping and preserve other writers' changes. Harvest builds missing `explored` lines from the session's own read history and continues. It stops for an operator answer only when a created or edited note has no first-touch record, when a recorded path does not exist and this session did not remove it, or when a resumed session has neither a usable record nor its earlier read history. Vault access is never reported as nothing to do.

End the session only on explicit `/harvest` or `$harvest`. A pause keeps the notes and claim. Harvest records one session retro, preserves proof and applies the current-state cleanup rules. Finalize and close-out retain their narrower compatibility contracts.
