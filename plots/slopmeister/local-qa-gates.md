`task check` is the one local gate here. Work that changes nothing a program or a session executes skips it, using the exemption in Review. Judge the effect of the edit, not its file type, directory or size. Changes to agent decisions, permissions, commands, workflow or required output run the gate. This includes instructions in skills, plots, the global source and documents they tell a session to follow. Treat a doubtful edit as behavioural. Exempt work still runs its affected document and render checks. The full gate adds the native install, dispatch, slot and vault tests to CI's portable layers. It also runs `bin/slopmeister workstation drift` against this machine's installed copies and, in a launcher-prepared worktree, its delivered configuration. Native dispatch needs the platform sleep guard and fixed service-action runtime. The native vault drive-sync suite needs real rclone. Home-install differences are notices in linked task worktrees. They still fail in the main checkout. The doctor and prepared-worktree comparison remain strict.

During editing, run the focused deterministic checks that address the changed behavior. When applicable, run the complete gate after the break-it pass and exact restoration. The runner uses up to eight concurrent check processes, keeps serial test groups apart, and fails on a missing or failed job. These checks use no model inference. Use `task check -- --report <report-path>` in the Git-ignored scratch directory in the task worktree when retaining evidence, and `bin/slopmeister check --list` to inspect the catalogue. Fixtures own their temporary state and processes, so routine checks usually need no peer coordination. Worktrees do not isolate shared ancestors. Keep the ancestor guard and other sessions' files. This section owns full-gate applicability. `docs/testing.md` owns test selection and evidence.

`task test:live` is the real-session smoke. It prepares a synthetic repository with this plot, runs one `sow` session per tool on a task with an open direction, and passes only when each session sends the one message before any edit, with the plain summary first, both options and one recommendation under Your call, a Proof line, and both length limits kept. It costs two real sessions, so name it under Details in the one message and run it once before the handoff, when the branch changes `plots/code/plot.md`, `src/skills/sow/**`, `src/skills/execute-plan/task-summary.md`, `plots/home/global.md`, `slopmeister/launch/**` or `slopmeister/install/**`. It never runs in `task check` or CI. The sessions read the installed global instructions, so a change to `plots/home/global.md` needs the operator's `task home:install` first. A change to `src/permissions.toml` is covered by `task check`, whose native layer drives both real clients against a stand-in model and requires every deny entry to be refused. Every other change gets deterministic tests and a rendered read.
