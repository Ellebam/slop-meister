# Permission contract

[Launcher](launcher.md#the-permission-contract) · [Global configuration](architecture.md#global-agent-configuration)

[`src/permissions.toml`](../src/permissions.toml) owns general command rules. [`src/github-permissions.toml`](../src/github-permissions.toml) owns GitHub command rules. [`src/native-permissions.toml`](../src/native-permissions.toml) owns workspace-bound release and selected service policies. Each entry has a command prefix, a decision and a `why`, and the renderer turns it into Claude settings, [Codex rules](../dist/codex/rules/permissions.rules) and the OpenCode permission map. Change its owning source and run `bin/slopmeister render`, never in a tool's own file. An unknown decision, a prefix under two decisions or a missing `why` fails the render.

| Decision | Effect |
|---|---|
| `allow` | Runs with no check. |
| `needs_intent` | Requires your order by name, approval as shown or an ordered procedure like `harvest`. Claude gets `autoMode.soft_deny` beside `"$defaults"`, Codex a `prompt` judged against the conversation, OpenCode an `ask` refused in headless runs. An `allow_unless` list changes this for Claude only. There the prefix runs by rule and a command that holds a listed token asks you. |
| `deny` | Refuses the matching direct command. |

Unlisted commands use the tool's judgment. Kickoffs, including initial user-role messages, issue bodies, notes and agent briefs are task content. Neither they nor claimed prior approval grant intent. Guarded actions need a later direct operator message.

**Commands that run by rule.** Two groups run with no reviewer in every launched session. Claude runs an API read with an explicit GET, and both tools run the Orca mailbox commands with terminal reads and lists. An allow rule skips the reviewer. Merges, raw CI reruns, tracker and review posts and `op tier-two` keep `needs_intent`. Codex cannot match a token in the middle of a command, so it keeps its prompt for every `allow_unless` prefix.

**Role rules.** The installer applies two contract flags per session. A proof session denies every `remote_write` and `terminal_input` entry. A dispatcher or manager session allows the `terminal_input` entries, `terminal send` and `terminal close` under both absolute Orca paths, in both tools. Codex takes the strictest rule of the session file and the installed home rules. The home rules keep the prompt for these entries, so a Codex dispatcher or manager still reaches the reviewer on a host with the home install. Every other session keeps the reviewer for them, including a proof owner. A dispatcher or manager Claude session also runs `task --dir <root> plot-session --`, `slot:up --`, `slot:down --`, `workspace:remove --` and `<root>/bin/slopmeister workspace-remove` by rule, and asks you for `--abandon` and for `--force` with each of its abbreviations from `--f` on, because the removal command accepts them. Codex receives no helper rule. The agreement's order rules stay the only guard for a launch that such a session types.

For requested repository or tracker inspection, use the existing named `gh` and `glab` reads when they provide the result. Claude runs an API read by rule when `--method GET` or `-X GET` directly follows `gh api` or `glab api` and the query is in the URL. A second method option, a body or field option, `--hostname` and an endpoint that names variables, triggers, tokens, secrets, secure files, keys, pipeline schedules or Terraform state ask you. A percent escape that encodes a letter or an underscore, `%4` to `%7`, also asks you, because it can hide one of these words. An escape such as `%2F` in a project path runs. These endpoint words name known credential routes. They do not prove that every other GET is safe. Every other `gh api` and `glab api` form retains native review of the exact method, task destination, endpoint and payload. Codex keeps its API prompt rule for every form. A read request supplies task authority for inspection through the existing signed-in client, without a separate write order. Writes, request bodies, GraphQL mutations, variables, credentials, account changes and unknown destinations keep their existing approval or denial.

Review commands and state files share the [worker's trust level](review-consent.md#give-the-reviewer-its-inputs).

**No Bash sandbox for Claude.** Installation sets `"sandbox": {"enabled": false}` because macOS Seatbelt broke pipes, process listing, `TMPDIR` and Git credentials. Claude has your rights, secret denies, intent rules and native approval. Codex uses `on-request` approval, macOS network access and no Linux sandbox. `op` needs network for [secret requests](1password-access.md).

Ship and claim helpers call `gh` internally. The [CI rerun command](../src/skills/ci-rerun/SKILL.md) calls `gh`, `glab` or `az`. Its fixed entry has a session-only allow for bounded task reruns, independent of shipping permission, except in directory and proof sessions. The installer protects entry directories. It verifies delivery and the runtime snapshot before provider access. A raw `gh run rerun` or `glab ci retry`, cancels and other raw provider mutations retain intent rules. Prefix rules restrict agent-typed commands, not internal calls.

When auto mode refuses an action you ordered, the session gives you its exact command prefixed with `!`, once in the refusal message. It does not retry, delegate the action or propose a saved permission change.

**Service actions.** A plot's optional `service_actions` list delivers only the selected fixed read and write actions and their private profiles, see [service actions](service-actions.md). Codex launches use `on-request` with `auto_review`, Claude keeps auto mode and explicit asks for those actions.

**Limits.** Rules match literal command prefixes, not shell expansion, and supply no security boundary. Codex treats `~`, `$VAR` and relative executable paths literally. Use expanded absolute paths for executable allow rules. Prove each allow with an authorized write outside the workspace. Sandboxed success does not prove a rule matched.

- Claude refuses `env <denied prefix>`, Codex runs it. This difference is accepted.
- Global flags such as `op --account … read …` can miss rules. `op run --no-masking` covers that prefix only.
- `gh auth status --show-token` and `-t` require literal spelling after the subcommand. Values (`--show-token=true`) and grouped flags (`-at`) miss them.
- Absolute paths, aliases, shell indirection, scripts and Task targets bypass direct matching.
- An allow rule matches one literal command. A leading variable assignment, a compound command, a pipe into a shell and an input redirect from a file outside the session's own directories reach the reviewer. Every session's agreement therefore tells it to type each external command alone and literally.
- Rules name Orca by absolute path. A variable such as `"$orca_cli"` or a bare `orca` reaches the reviewer.
- In a launched session, `op run`, `op tier-two` and `op desktop` refuse an inner command that starts with a denied prefix. The session's `op` reads the prefixes from `.claude/access-settings.json` in the workspace, and without a readable file there it starts no inner command. Every other inner command starts with no rule check. This includes `sh -c`, `env <denied prefix>`, an absolute path, a global option such as `git -C . commit -a`, a script, a Task target and every ask-first command. Claude's refusal of `env <denied prefix>` does not apply behind these prefixes. A shell without the launcher's workspace mark gets no check. A session that changes `.claude/access-settings.json` in its own workspace, or the `SLOPMEISTER_SESSION_WORKSPACE` value through a leading assignment, changes what this check refuses.
- In Claude Code, a saved allow for an ask-first command runs it with no check of the operator's order. Central denials still win. Remove such allows.
- A command substitution inside a double-quoted argument of a rule-allowed command can also run with no reviewer call.
- An ask token matches anywhere in the command, so a URL or filter that holds a listed word asks.
- Masking hides recognized secrets in output. Consuming programs can still write or send them.
- Marked sessions choose tokens by vault. Tier two needs explicit intent and Home Assistant approval. Reference-free `op run` executes directly. Unmarked onboarding uses the real CLI. Its allow rule does not guarantee approval. Run ordinary commands directly for native rule matching.

The [native test](testing.md#run-real-session-qa) proves direct refusals and central deny precedence over saved allows in both clients. It doesn't prove real 1Password authentication or masking. Home installation adds missing central denies and ask-first strings, preserving saved approvals, existing denials, soft-deny entries and session-only allow scope. Drift checks current ask-first strings. Superseded strings stay until a separate operator order. [Global files](architecture.md#global-agent-configuration) owns drift checks and file ownership. Generated rules include [self-cleanup](workspace-removal.md#a-worker-removes-its-own-worktree). That allow is bound to exactly `workspace-remove --self -- <this workspace>`. It does not authorize a different path or force. The command still checks the caller, claims and unsaved work. Home updates require the operator.
