## The independent check and readable handoff

Follow [operator proof](1password-access.md#prove-the-route) for real approvals, dialogs and reboot. Run `.venv/bin/python -m pytest -q tests/unit/session tests/integration/session/test_secret_run.py tests/integration/workstation/test_op_setup.py tests/native/install/test_permission_op.py tests/integration/render/test_permission_contract.py` for the session's `op` against a stand-in real `op` and a stand-in Home Assistant, the setup step and the native rules.

For the shared [task summary](../src/skills/execute-plan/task-summary.md), run `.venv/bin/python -m pytest -q tests/integration/spine/test_rendered.py tests/integration/render/test_procedures.py`. These checks cover caller references, tool parity and stateless reassessment. There is deliberately no report-shape or milestone parser. Readability and session compliance need a fresh small spine task in each tool and the operator's acceptance.

For selected service actions, run `.venv/bin/python -m pytest -q tests/unit/session/service_actions tests/integration/install/test_service_actions_*.py tests/native/install/test_service_action*.py tests/unit/plots`. Portable tests cover provider behavior, shared operations, profile admission, workspace delivery, snapshots, cancellation and diagnostics. Native tests drive the fixed curl on each system against disposable PAT-only and PKCS#12 HTTPS servers and check exact entry-command approval-rule precedence. Only the disposable certificate generator runs through system Python with its installed `cryptography`. The delivered session and pytest environment remain standard-library-only. The suites use no real 1Password or provider credentials. `tests/integration/install/test_service_actions_server_ca.py` covers profile pins and `tests/native/install/test_service_actions_server_ca.py` drives their TLS enforcement. Native approval behavior and real ticket retrieval require the separately authorized [service-action proof](service-actions.md#verify).

The independent diff check starts from a clean copy of the committed or frozen candidate, without development dependencies or worker scratch. Its guide owns setup and runnable scenarios. Run `bin/slopmeister review review --direction <direction> --mode diff --cwd <checkout> --guide <absolute-guide> --prompt-file <prompt>`. Use this checkout's binary when present. With commits denied, add `--candidate`. The launcher-confirmed task owns the saved result. Repeating the command replays that result rather than launching another reviewer.

Add `--slot-target <plot>` when the guide needs separate ports or Compose resources. The [check allocation](slots.md#independent-checks) belongs to the existing slot owner. The check executes each required scenario itself. Worker evidence cannot substitute. It may create fixture files in its copy but cannot change the tested files or HEAD. It also checks that the worker's original tree stays unchanged.

Save command output under the run's `evidence/` directory. Each reported pass or fail needs a nonempty exact quote from a saved file there. A quote of the guide, a worker file, an absent file or invented text is not proof. Missing, repeated or unproven scenarios become `could_not_run`. `TEST_FAIL` and `TEST_INCOMPLETE` block the gate. Keep their exact statuses and any guide findings. Additional defects are findings, never silently added required scenarios.

The review process owns its process group. Timeout or uncertain shutdown retains the checkout and any slot. Confirmed shutdown releases its slot and removes only its own checkout, including read-only caches. Failed teardown retains the checkout and reports the cleanup error. The run keeps its guide and evidence outside the checkout. Do not substitute a later passing run for retained failure evidence or replace a completed review without authority.

Review output is sanitized before display. Recognized credentials and labelled sensitive assignments are masked. Unknown, unlabelled secrets may remain, so keep raw evidence private and inspect exact outward text before publication. The same-user process boundary does not protect against hostile code running as the operator. Run only authorized target code and use the host isolation required by its guide.

For an expected empty result, check command success and subject activity before saving a nonempty assertion marker. An unconditional success marker proves nothing. The [test-guide procedure](../src/skills/test-guide/SKILL.md) owns scenario format and operator-only checks.

OpenCode checks use a fake `opencode` from `tests/support/opencode_fake.py` and never call a provider. Run `.venv/bin/python -m pytest tests/integration/opencode tests/integration/launch/test_opencode.py tests/unit/threads/test_opencode_occupants.py -q -p no:cacheprovider` for native evidence, the launch line, argument refusal, occupancy and startup refusal. A live OpenCode proof needs the operator's provider reachable and its variable in `~/.zshenv`, see [OpenCode](opencode.md).

Task notes are ordinary untracked Markdown and can be corrected or selectively updated without a recovery command. Producer results are different. Read the exact evidence run recorded in the notes and replay the review's protected task-and-mode result. A candidate-bound result validates the current tree identity before replay and refuses substitution without launching. Shipping keeps no result file, Git and the PR show what shipped, and a rerun of ship never repeats a confirmed write. A permission error or a failed or blocked producer does not authorize another external session, result replacement or alternate state namespace.

## Test files and cleanup

The runner and process-sensitive suites create short private `/private/tmp/htr.<random>/` roots. `owner.json` names the folder and the gate's PID and kernel start identity. Gate jobs receive separate `TMPDIR` values. Fixture homes, sockets, repositories and reproducer files stay beneath owned roots. Normal HOME remains available for binary discovery and installed-drift checks. Native listener fixtures bind port 0 and keep the assigned socket open.

Native harvest proof uses the task guide's declared fixture paths and expected final state. Sessions create no automatic retro note. Derive any index expectation from the actual file shape and permitted paths, never an assumed README table row. After acceptance and authorized cleanup, remove only exact recorded test files whose bytes match the expected final state, preserving unrelated or changed files. Use `slopmeister-vault commit` for the named vault paths. Whole-vault manifests taken before and after every turn show changes outside the scenario's paths. The [test-guide examples](../src/skills/test-guide/SKILL.md) cover scoped first-turn instructions, attributable operator answers and owned-file cleanup.

No automated test writes into the real vault, vault tests run against disposable subject trees under their own temporary directory. A leftover note in the vault's `_system/test-fixtures/` is removed only by exact path with operator approval, and only while `vaultgit ls-files --error-unmatch -- <path>` succeeds and `vaultgit status --porcelain -- <path>` prints nothing, both checked immediately before the delete, so history can restore it. Commit the removals by name with `slopmeister-vault commit`. A prefix, marker or age alone never authorizes a removal.

Cleanup and debloat sessions use `bin/slopmeister check --clean` for `/private/tmp/htr.*` run folders instead of deleting them by hand, because it applies the [runner ownership and liveness rules](testing.md#which-command). A prefix, PID alone or age is never deletion authority. Ordinary workstation gates share the existing blocking file lock. CI, listing and cleanup bypass it. There is no shared scheduler or background cleanup service.


## Run real session QA

Native startup tests use inert tool servers and verify that no model request or service action runs. Browser page-control proof uses a task-owned HTTPS fixture, synthetic credentials and an explicitly selected isolated profile. Neither substitutes for approved live-account checks.

Use the cheapest layer that observes behavior. Registry tests check required entries independently of generic translation tests. `tests/native/install/test_discovery.py` checks delivered configuration loading. `tests/native/install/test_permissions.py` drives both clients through `tests/support/standin.py`, a loopback model with scripted calls. It requires every contract deny's direct bare and argument forms to be refused and records the `env` difference. Marker stubs and unrefused controls prove execution safely. `tests/native/install/test_permission_intent.py` checks cleanup prompt precedence over inherited allows in Codex's policy engine and the unlisted direct-PID kill control. Deterministic checks do not prove real approval-model judgment. Live scenarios use harmless stubs and record decisions. Start and stop a disposable child within one client shell command so PID namespaces cannot invalidate the control.

`task test:live` runs one `sow` session per tool, with operator consent. Neither may change tracked files, and each must send the one message, plain summary first, both options under Your call, with a Proof line and within both limits. Each session has 300 seconds, no retries or grading model. The live layer runs only when named explicitly. See the [plot's trigger rule](../plots/slopmeister/local-qa-gates.md).

The smoke uses the operator's normal login and home, so native session history lands there and the installed global instructions are the ones it reads. Missing login or rate limits are a blocked result, not a failure. Each session's command, output and errors stay under pytest's temporary directory. Read them before recording a pass or fail.

Documentation scenarios use the current task's guide and separate operator consent, keeping the smoke unchanged. Bind native write grants and vault, history and spill routes to disposable fixtures before a write-capable session. Record remote calls, verify containment and stop if isolation is unproven. Harvest authority/refusal scenarios must stop before any unapproved remote command. Preserve harvest’s document ownership, action-specific approval and recovery stops.

The full spine needs no separate orchestration harness. Every real task uses the independent diff check and its runnable guide. Real operator or proof-owner sessions establish instruction compliance. Deterministic fixtures cover the branch, candidate, ownership and containment rules.

The launcher accepts individual Codex `mcp_servers.<name>.enabled=false` overrides for disabling inherited connections. Enabling, replacing or bundling connection settings remains refused. These invocation options leave the normal account configuration unchanged.
