# Launcher recovery

[The launcher](launcher.md) · [All documentation](README.md)

Orca terminal creation failures print its code, `timeout`, `unreadable_reply` or `execution_failed` on one line. Only `selector_not_found` permits retries within 60 seconds, including call timeouts. Every failure then polls, because a terminal may exist.

`--abandon --handoff <absolute-notes>` stops a worker and its descendants child-first and verifies exit through the same closure as redispatch. It requires a saved nonempty handoff inside the worker workspace, excludes redispatch, and preserves the workspace, branch, notes and companion repositories. Without an issue association, including manual-task, vault-task and directory plots, it touches no tracker and writes no claim. A claimed GitHub worker keeps its [claim release](issue-claims.md) and open issue. Add `--directory` for a directory session and `--host <alias>` for a remote stop, with the handoff path on that host. After a closure refusal, inspect the worker and retry the same abandon command. Each claim-free abandon acts on the current worker, so check the session before repeating it.

`--redispatch` preserves the workspace, branch, files, notes, configuration and slot. Keep the saved task branch checked out, including when continuing a pull request. It validates identity, configuration, native settings, permission, delivery exclusion and required native-tool startup before stopping the worker. Mismatches leave the worker running. It records and stops the agent and descendants child-first, then verifies their exit. It closes the saved terminal only after stopping a live predecessor, because idle tabs may be someone's shell. The close request and repeated inventory checks share a ten-second monotonic deadline, followed by one final inventory check limited to half a second. A terminal still listed or unreadable at that final check refuses without a replacement. The same bounded closure serves harvest. The new conversation receives the kickoff and retains the fixed snapshot. It also takes over its predecessor's Orca Run, saved in the private `tmp/plot-session/<name>.run`, so mail sent to the old address reaches it. A failed takeover creates no second Run and gives the new conversation the inbox notice. A fresh launch starts a new Run.

[Automatic context redispatch](../src/skills/plot-session/dispatcher.md#automatic-context-redispatch) is the default after three native compactions. The worker saves its notes, handoff and restart command before sending one request to its verified dispatcher. The dispatcher or the worker's sole manager independently checks fresh Context Meter figures, the current native identity, ended turn, evaluated null wait and saved state. A question, an open deployment window, an unknown figure or an unavailable host prevents replacement. A manager's open operator question does not, when its saved handoff states it verbatim. Model and effort come from the original private launcher command and native metadata, cross-checked against the handoff. This path needs no operator order or Night mode. Other recovery and abandonment authority stays unchanged.

Redispatch validates each recorded repository's location, branch, registration and permissions before stopping the worker. It adopts existing companions without reallocating them. Missing or pending members need recovery. Inspect their recorded destination and Git registration, preserve uncertain work and never erase a record to bypass refusal. Repositories added after freezing require a new combined candidate and proof. A prior review cannot cover the expanded set.

A workspace from before the removal of the Git guard refuses redispatch, and `git config --worktree --unset core.hooksPath` restores ordinary Git there. Independently running services keep running, those owned by the old agent may need restarting.
