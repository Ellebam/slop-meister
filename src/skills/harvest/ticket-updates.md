# Ticket updates at harvest

A plot whose vault has `fields/<plot>/tickets.md` sends ticket updates only as the operator approved them at the handoff, as the [task summary](../execute-plan/task-summary.md#ticket-updates) describes. This replaces the step 4 rows for a tracker outside the repository. A managed GitHub issue keeps its claims flow.

Read the answer recorded in the notes. Send each approved item exactly as approved, or as the operator edited it, through the definition's write route and its native approval. Before the first write to a ticket, read it fresh. When its last-update time differs from the one in the proposal, or, where the tracker shows none, a proposed current value differs or its items record none, send nothing to that ticket. A write route through the operator puts the approved item into the report as text ready to carry in.

Harvest never asks a ticket question. A ticket update never pauses harvest or fails a step. A Night mode grant approves no ticket update. Every unapproved, unanswered, changed, refused or unsent item, including one an earlier failed step left unsent, goes into the report as a draft with its exact text and the reason it was not sent.
